When I first asked AI to help with a project, my assumption was simple: if I described the requirement clearly, the model could generate the rest.

UE Toolkit showed me why that is incomplete. AI can generate a UI or an API quickly, but it does not know whether the feature solves a real user problem or whether a result that runs once belongs in a product.

I gradually developed a more cautious process: break down the requirement, check the relevant material, build a small prototype, run it myself, feed concrete failures back to the AI, and only then decide whether to release it.

## A shared asset library cannot only “read successfully”

A shared library initially looked like a small task: read assets from a network location and show a list with thumbnails.

Real use exposed several separate cases. The first load could be slow. A thumbnail failure should not make the whole batch look complete. Switching or removing a connection should not leave the UI stuck in a loading state. A validated preview copy should not be downloaded again on every refresh.

I split this into independently checkable changes: store the file manifest separately, reuse validated preview material, isolate temporary preview workspaces, add safe recovery and retry after creation failures, and then check deletion, switching, thumbnail failures, and concurrent refreshes.

The AI helped with local logic, tests, and verification scripts. I still had to check that a second open really avoided a full download, that a failed creation could be retried, and that an old task could not write back into the current page after a connection switch.

## A scroll problem was not “make the list faster”

Another example was mouse-wheel response in the project and asset catalogs. A more elaborate painting path had been introduced while working on card rendering. In actual use, the important question was simpler: after turning the wheel, does the list move immediately?

The measured behavior showed that the custom wheel animation delayed the first visible movement. The fix was to restore a more direct response path and verify the interaction after switching side panels, rather than adding another layer of optimization.

This changed how I think about performance work. A passing test or a complicated rendering path is not the same as a comfortable user action.

## How I work with AI now

I start with a reproducible symptom. Then I ask AI to help identify likely causes and the smallest safe change. When several modules are involved, I check the data flow and page state before splitting the work into smaller tasks.

AI can help with research, interfaces, tests, and debugging. It cannot decide the product priority, define what “done” means, or replace human acceptance.

For me, AI-assisted development means putting the model inside a process with clear requirements, version history, real operation, and user feedback. It does not mean claiming that the model wrote a finished product on its own.
