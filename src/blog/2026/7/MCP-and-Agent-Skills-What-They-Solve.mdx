When I first encountered MCP and Agent Skills, I treated both as plugins that made AI more capable. After putting them into the context of AI application development, I found that they solve different problems.

In simple terms, MCP answers “how can an AI client connect to tools and data?” Agent Skills answer “how should the AI complete a recurring kind of task?” One is a shared interface; the other is a reusable way of working.

## MCP solves the connection problem

Without a common protocol, every AI client needs a separate adapter for every service. MCP separates the roles of Host, Transport, and Server. The client manages the AI and its connections, the transport carries messages, and the server exposes tools, resources, or prompts.

There is an easy misunderstanding here: an MCP Server does not have to be a remote server. It can run as a local process, inside a container, or on another host. Whether it uses the network depends on what the implementation actually does.

## Agent Skills solve the packaging problem

A Skill is closer to a reusable set of instructions. It can contain rules, scripts, references, and output requirements. When a similar task appears, the AI can load the needed parts instead of rebuilding the whole procedure from a long prompt.

I currently think about a Skill in three layers: a description tells the AI when it applies, `SKILL.md` defines the workflow, and scripts or references are loaded only when needed. This keeps the capability inspectable and avoids filling every context window with irrelevant details.

## How they work together

A Skill can require a workflow such as checking project state, calling a tool, and performing human acceptance. MCP can provide the interfaces for reading files, querying data, or performing an action.

Neither one replaces judgment. MCP connects tools, and Skills preserve methods. Permissions, data flow, and results still need to be checked by a person.

## What I take from this

AI application engineering is more than connecting a model to an API. It also requires decisions about tool connections, reusable capabilities, permissions, and verification. MCP and Agent Skills reduce repeated work in those areas.

I have not turned them into a complicated multi-agent platform. For my current work, the practical approach is to clarify a task first, then decide whether it needs a tool interface, a reusable workflow, or neither.
